## 🏗️ 多进程架构

### 设计思路

**生产者 - 消费者模式（多进程实现）**

```
┌─────────────────┐         ┌─────────────────┐
│   主进程        │         │   推理进程      │
│  (解码 + 预处理) │ ──────→ │   (GPU 推理)    │
│  CPU 核 1-4     │  Queue  │  CPU 核 5-6 + GPU│
└─────────────────┘         └─────────────────┘
      ↓                            ↓
  共享内存                    结果输出
```

### 进程分工

#### **主进程（生产者）**
- **职责**: RTSP 拉流 + 硬件解码 + 预处理
- **CPU 核心**: 1-4 核
- **任务**:
  1. 解码器：DXVA2 硬件解码
  2. 共享内存读取：零拷贝传输
  3. 预处理：YUV→RGB 转换（OpenCV 加速）
  4. 数据传递：通过 Queue 传给推理进程

#### **推理进程（消费者）**
- **职责**: YOLO 模型 GPU 推理
- **CPU 核心**: 5-6 核
- **GPU**: CUDA Execution Provider
- **任务**:
  1. 加载 YOLO11n 模型
  2. GPU 推理（33.7ms）
  3. NMS 后处理
  4. 类别过滤（person, car）

## 🎯 与单进程对比

### 单进程瓶颈

```
串行执行：
解码 → 预处理 → 推理 → 后处理
  ↓        ↓        ↓       ↓
  CPU     CPU      GPU     CPU
  (等待)  (等待)   (等待)  (等待)

总耗时 = 5 + 10 + 7.5 + 33.7 + 3 = 59.2ms
FPS = 1000/59.2 = 16.9（理论）
实际 FPS = 12.9（系统开销）
```

### 多进程优势

```
并行执行：
时间轴 →
解码 1 → 预处理 1 → ╭─→ 推理 1
解码 2 → 预处理 2 → ╰─→ 推理 2
解码 3 → 预处理 3 → ╭─→ 推理 3
...

GPU 持续工作，无等待！
```
