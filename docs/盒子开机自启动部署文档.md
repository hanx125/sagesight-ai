# 盒子开机自启动部署文档

本文档说明如何在 RK3588 盒子上配置 SageSight AI 平台的开机自启动，使用 systemd 服务方式实现。

## 一、服务文件内容

创建服务文件 `/etc/systemd/system/sagesight.service`，写入以下内容：

```ini
[Unit]
Description=SageSight AI Detection System
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=root
WorkingDirectory=/root/sagesight-ai
ExecStart=/usr/bin/python3 /root/sagesight-ai/run.py
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

### 设计说明

- **`After=network-online.target`** **+** **`Wants=network-online.target`**：等待网络就绪后再启动，避免首次连接 MinIO/MQTT/FTP 时网络未通。配合 `Restart=always` 和 `RestartSec=10`，即使首次连接失败也会自动重试。

- **`WorkingDirectory=/root/sagesight-ai`**：项目通过 `Path(__file__).parent` 定位根目录、相对路径读取 `config/system_config.yaml` 和 `logs/`，必须设置正确的工作目录。

- **`ExecStart=/usr/bin/python3`**：使用系统 Python（盒子上依赖已装在系统 Python 中，未使用虚拟环境）。若部署时改用 venv，需相应修改为 `/root/sagesight-ai/venv/bin/python`。

- **未使用** **`StandardOutput=append:`** **/** **`StandardError=append:`**：项目内部已通过 LogManager 将业务日志写入 `logs/system.log`（带大小滚动和备份，配置见 `config/system_config.yaml` 的 `logging` 段），若再追加 append 会重复写一份且不滚动，容易撑满磁盘。控制台输出交给 journald 收集。

- **`User=root`**：RK3588 平台 RGA 与 NPU 需访问 `/dev/dri/*`、`/dev/rknpu` 等设备节点，root 用户无需额外权限。若改用非 root 用户，需将用户加入 `video` 和 `render` 组。

## 二、启用步骤

按以下顺序在盒子上执行：

```bash
# 1. 写入服务文件
sudo nano /etc/systemd/system/sagesight.service
# 粘贴上面的内容，保存退出（Ctrl+O 回车保存，Ctrl+X 退出）

# 2. 重载 systemd
sudo systemctl daemon-reload

# 3. 启用开机自启
sudo systemctl enable sagesight.service

# 4. 立即启动（先手动跑一次确认能起）
sudo systemctl start sagesight.service

# 5. 看状态（应为 active running）
sudo systemctl status sagesight.service

# 6. 看启动日志（确认无报错）
sudo journalctl -u sagesight.service -n 50 --no-pager
```

### nano 粘贴注意事项

nano 默认会自动缩进，可能导致每行前面多出空格。粘贴前建议先关掉自动缩进：

- 按 `Alt + M`（或 `Esc` 然后按 `M`）切换掉 auto-indent

- 粘贴后检查每行开头是否有多余空格，有就删掉

> systemd 配置文件对行首空格不敏感，但 `[Unit]`/`[Service]` 这类段名必须顶格，不能有前导空格。

## 三、验证开机自启是否生效

重启盒子验证一次最稳：

```bash
sudo reboot
# 重启后等 30 秒登录
sudo systemctl status sagesight.service   # 应为 active (running)
```

`Loaded: ... enabled` 表示开机自启已启用，`Active: active (running)` 表示服务正在运行。

## 四、日常管理命令

```bash
sudo systemctl stop sagesight.service       # 停止
sudo systemctl restart sagesight.service    # 重启
sudo systemctl disable sagesight.service    # 取消开机自启
sudo journalctl -u sagesight.service -f     # 实时看控制台日志
tail -f /root/sagesight-ai/logs/system.log  # 看业务日志（带滚动）
```

## 五、日志说明

项目存在两份日志，用途不同：

| 日志来源     | 查看命令                                         | 内容                                               |
| -------- | -------------------------------------------- | ------------------------------------------------ |
| journald | `sudo journalctl -u sagesight.service -f`    | `run.py` 的 stdout/stderr，包含启动信息、未捕获异常的 traceback |
| 业务日志     | `tail -f /root/sagesight-ai/logs/system.log` | `logger.info()` 写入的业务日志，包含任务启停、事件产生、检测统计等        |

- 日常排查业务问题优先看 `system.log`（带大小滚动和备份，配置见 `config/system_config.yaml` 的 `logging` 段）。

- 服务起不来时看 `journalctl`，能看到 Python 启动阶段的报错（如 `ModuleNotFoundError`、端口占用等）。

## 六、部署前检查清单

启用服务前，在盒子上跑一遍确认：

```bash
# 1. 确认解释器路径正确（能导入项目依赖）
/usr/bin/python3 -c "import flask, eventlet, psutil, requests; print('OK')"

# 2. 确认手动启动正常
cd /root/sagesight-ai && /usr/bin/python3 run.py

# 3. 启用服务后看状态
sudo systemctl status sagesight.service
sudo journalctl -u sagesight.service -n 50 --no-pager
```

## 七、故障排查

### `systemctl status` 显示 failed 或 inactive

查看详细日志定位原因：

```bash
sudo journalctl -u sagesight.service -n 50 --no-pager
```

常见原因：

- **`ModuleNotFoundError`**：依赖未装在系统 Python 中。检查 `/usr/bin/python3 -m pip show flask` 的 Location，确认依赖路径。若依赖装在 `/root/.local/`，需在 service 文件 `[Service]` 段加：

  ```ini
  Environment=PYTHONPATH=/root/.local/lib/python3.11/site-packages
  ```

  （路径换成实际 Python 版本对应的目录）

- **端口占用**：`run.py` 默认监听 5556 端口（由 `config/system_config.yaml` 的 `web_server.port` 控制），确认未被其他进程占用：

  ```bash
  ss -tlnp | grep 5556
  ```

- **配置文件错误**：检查 `config/system_config.yaml` 语法是否正确：

  ```bash
  /usr/bin/python3 -c "import yaml; yaml.safe_load(open('/root/sagesight-ai/config/system_config.yaml'))"
  ```

### 服务运行但功能异常

查看业务日志：

```bash
tail -n 100 /root/sagesight-ai/logs/system.log
```

### RGA / NPU 相关错误

确认设备节点权限：

```bash
ls -l /dev/dri/* /dev/rknpu
# root 用户应能正常访问；非 root 用户需加入 video 和 render 组
```
